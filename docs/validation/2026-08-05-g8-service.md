## 1. P5a foreground unplug/replug recovery

1. A foreground `n3-ai-deck-service` run with the USB cable unplugged walked
   the capped back-off schedule `2 s → 5 s → 10 s → 30 s` while the node was
   absent (`DEFAULT_BACKOFF_SCHEDULE = (2.0, 5.0, 10.0, 30.0)`).
2. Permission-rejected sessions back off too — this was the hot-loop defect:
   before `4c161d5`, a rejected session retried immediately in a tight loop
   instead of backing off. `4c161d5` fixed it, and the observed run logged
   **4 sessions / 5 retries**.
3. SIGTERM produced a clean stop: the final summary reported
   `stopped_cleanly: true` alongside the `sessions_run` / `retries` counts.

## 2. Log flush fix (`dcf2af7`)

1. stdout line buffering is configured at CLI startup in `service_cli.py`
   (`_configure_line_buffered_stdout`) and in `live_cli.py`, both via
   `sys.stdout.reconfigure(line_buffering=True)` behind a guard that leaves a
   replaced test-runner stdout alone.
2. journald therefore receives every JSONL line immediately instead of in
   block-buffered bursts or stuck buffered lines.
3. After the fix the local suite was green: **994 passed**.

## 3. Real user self-install

1. `uv tool install` of the working tree installed **all 10 console scripts**
   into `~/.local/bin`.
2. The stock `--print-unit` user unit was installed **unchanged** at

3. `systemctl --user enable --now n3-ai-deck` started the service

## 4. udev rule defect found during install

1. The rule printed before this record could never match on the real system:
   a single line combined `ATTRS{idVendor}` / `ATTRS{idProduct}` (attributes
   of the usb_device parent) with `ATTRS{bInterfaceClass}` /
   `ATTRS{bInterfaceSubClass}` / `ATTRS{bInterfaceProtocol}` (attributes of
   the usb_interface parent). A udev rule's `ATTRS{}` matches may draw from
   the event device plus **exactly one** parent device, so the combined line
   always failed to match.
2. The originally recommended `99-*` filename sorts **after**
   `73-seat-late.rules`, where the `uaccess` builtin takes effect — so even a
   matching rule would never have applied the tag.
3. `88030e1` fixed both: the generated rule is **USB-device-level only**
   (idVendor/idProduct + `TAG+="uaccess"`), and the install recommendation is
   `/etc/udev/rules.d/60-n3-ai-deck.rules` (must sort before
   `73-seat-late.rules`). The docs were swept to match, and the local suite
   went to **996 passed**.

## 5. End-to-end result with the corrected rule

1. The corrected `60-n3-ai-deck.rules` was installed, then
   `udevadm control --reload` and `udevadm trigger` ran.
2. The `uaccess` ACL was applied **automatically** to the hidraw and input
   event nodes — no manual `setfacl`.
3. The systemd service session went from permission-rejected to a full
   **succeeded 60 s session**.
4. The end-to-end automation test passed: the owner unplugged and replugged
   the USB cable with **no manual `setfacl`**, waited ~10 s, pressed LCD key 1
   and got the green feedback flash. The test passed **twice** — once before
   and once after the replug.
